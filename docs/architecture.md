# Architecture

## System Topology

ClearSplit is a client-server system:

- iOS app (SwiftUI) handles UI, local state, and token storage.
- FastAPI backend exposes REST endpoints and enforces domain rules.
- PostgreSQL stores all durable relational data.
- S3-compatible object storage stores receipt images.
- Tesseract OCR is used server-side for receipt text extraction.

## Request Lifecycle

1. iOS sends JSON or multipart request to FastAPI.
2. Backend authenticates user from bearer access token when required.
3. Route delegates to service-layer business logic.
4. Service enforces permissions and domain invariants.
5. SQLAlchemy persists/reads data from PostgreSQL.
6. Response is serialized via Pydantic schemas and returned.

## Backend Design Principles

- Thin route handlers, service-layer business logic.
- Role-aware permissions (`owner`, `member`, `viewer`) at service boundaries.
- Deterministic split arithmetic (integer cents, stable remainder handling).
- Idempotency support on mutation endpoints where duplicate submission is likely.
- Strong group-scoped relational integrity with composite foreign keys.

## Core Domain Flows

### Authentication

- Access tokens are short-lived JWTs.
- Refresh tokens include JTI and are persisted in `refresh_tokens`.
- Refresh rotates JTI and revokes old token row to prevent replay.

### Expense and balance computation

- Expenses create payer contribution + split obligations.
- Live balance engine computes `paid - owed` per membership.
- Transfer suggestions are generated by matching debtors to creditors greedily.

### Settlement payments

- Payments can be pending or confirmed.
- Confirmed payments feed back into live balances.
- Covered shopping sessions can auto-transition to `settled` once net for that session reaches zero.

### Shopping sessions

- Session lifecycle: `active -> finalized -> settled`.
- Financial mutations can reopen `settled` sessions to `active`.
- Participant changes trigger split regeneration for existing items.

### Receipt and OCR pipeline

- Upload validates content type, image format, file size, and pixel limits.
- Exactly one receipt is allowed per shopping session.
- OCR extraction is concurrency-limited and time-bounded.
- Parsed lines are filtered by confidence heuristics before persistence.

## iOS Architecture

- `AppState` is the central source of truth for authenticated session data.
- Domain service wrappers (`AuthService`, `GroupsService`, etc.) sit on top of `APIClient`.
- `APIClient` handles auth header injection, token refresh on 401, and snake_case JSON conversion.
- ViewModels and Views are organized by feature area with reusable components.

## Security-Critical Behaviors

- Non-local environments require explicit HTTPS CORS origins.
- Trusted-proxy header handling is opt-in and allowlist-based.
- Rate limiting protects signup, login, and invite-preview endpoints.
- Receipt processing defends against malformed/oversized image payloads.
